Poker client audit: engine, server, desktop shell and table UI

VERDICT — FIXED AND COMMITTED ON THE AUDIT BRANCH; NOT PUSHED OR PACKAGED.

The audit found 8 critical and 16 high-severity defects. All 24 are fixed and covered by tests. The suite went from 18 to 67 passing tests, the TypeScript check is clean and the production build succeeds. The fixed build was exercised in a browser against a throwaway database.

One thing is not done: the branch is not pushed and the app is not repackaged, so the installed ~/Applications/DanGG.ro.app still runs the old code. The Electron shell changes were launched and checked on an isolated profile (10 of 10 checks passed).

Scope and method

Every line of the poker engine (poker.js, table.js), the HTTP and WebSocket server (index.js, db.js), the Electron shell and the table page was read. The lobby, cashier, rewards, casino and admin pages were checked only where they call an endpoint that changed. Each defect was reproduced by reasoning from the source or by a failing test before it was fixed, and each fix has a test or a measurement recorded below.

The clone's artwork is generated locally and is not in this checkout, so the browser check ran without images. Layout fidelity to the original client was not assessed.

Fixed: medium and low

  • Table could stall on an absent player. Two consecutive timeouts now sit the player out; elimination formats deal sitting-out players in and fold them, so nobody can freeze a tournament. A live hand with no actor heals itself on the next tick.
  • Opening hand was dealt heads-up to the human and the first bot while the remaining bots were still being seated.
  • Pot button used the wrong formula (pot × f + bet). It now calls first, then raises by the fraction of the resulting pot.
  • Login matched a nickname as well as an account ID, and nicknames were not unique, so a look-alike nickname could shadow an account or impersonate a player in chat. Nicknames are unique, validated and cannot equal another account's ID.
  • Password comparison was not constant-time; minimum length was 4. Now timingSafeEqual and 6.
  • Static file serving accepted sibling-prefix paths (dist-old/… passed the startsWith(dist) check) and threw a 500 on malformed escapes.
  • Server errors echoed the exception message to the client.
  • No security headers. Added nosniff, X-Frame-Options, Referrer-Policy and a Content-Security-Policy on the HTML shell. The built app ran under the policy with no violations.
  • Casino bets with an unknown type lost the stake silently. Roulette, baccarat, dragon-tiger, sic bo and prop bets now reject them. Roulette gained the column bets the README already listed.
  • Baccarat player and banker bets lost on a tie; they now push.
  • Banning a player left their sessions and seat alive. A password reset by an admin left sessions alive and defaulted to a known password. Deleting a user left orphaned sessions and no audit entry.
  • Maintenance flag was never enforced. Non-admins can no longer take a seat while it is on.
  • XP and VIP points never changed, so the "Earn 500 VIP points" mission could not progress. Hands now award XP, and raked hands award a point.
  • Chat and emotes were unbounded. Rate-limited; emotes capped at four characters; socket frames capped at 16 KB; settings blobs capped at 64 KB.
  • Unregistering did not decrement the entrant count; registration ignored status and capacity.
  • Mission progress was credited to seated players who were not dealt into the hand.
  • Database: expired sessions are purged at start; indexes added for per-user ledger and session lookups.
  • Table UI: the blinds pill showed "1/1" for a $0.50/$1 table; the turn timer assumed 15 seconds and the local clock; the bet box could not enter half-dollar amounts on micro-stakes tables; the sit-out toggle was local state that drifted from the server; tournament observers were offered a "Take a seat" button that could not work.
  • .gitignore ignored the node_modules directory but not a symlink of that name.

Improvements added

  • Pre-actions. Check/Fold, Check and Call can be queued while waiting. A queued call is cancelled if the price changes.
  • Sizing presets. 2.5x, 3x and 4x the big blind for an unopened pot; 33%, 50%, 75% and pot after that; a Max button at pot-limit tables.
  • Pot odds beside the Call button: the price and the win rate needed to break even.
  • Reconnect. Players who drop show as "Reconnecting" and return to the same seat and stack.
  • "I'm back" banner when sitting out, and an "away" badge on other players.
  • Pure, tested modules for bet maths (src/game/betting.ts), slots, validation, request security and hand-history projection, instead of more code in the 1,400-line server file.

Checked in a browser

  • Production build served by the fixed server on port 5310 with an empty database in a temporary directory. The installed app and its database were not touched.
  • Login; a $0.50/$1 Hold'em table; a PLO table showing four hole cards, the pot-limit label and a Max button.
  • Pot odds read "3.0:1 · need 25%" facing a half-blind call into $1.50, and "1.5:1 · need 40%" facing $10 into $15.
  • Letting the timer run out twice produced the sitting-out banner. Reloading the page returned to the same seat with the $200 stack and no second buy-in. "I'm back" dealt the player in, a call registered, and the pre-action row appeared while waiting.
  • No Content-Security-Policy violations or script errors in the console. The only errors were 404s for the artwork that is not in this checkout.

Checked in the Electron shell

Electron 38.8.6 was launched from this branch with GGPOKER_USER_DATA pointing at a temporary profile and GGPOKER_PORT=5320, then driven over the DevTools protocol. The installed app and its database were not touched.

  • The main window loads the local server and the app renders with the renderer sandbox on.
  • The preload bridge works under the sandbox; no Node globals (require, process) are reachable from the page.
  • A popped-out window gets its own bridge, and its close button closes only that window; the main window stays open.
  • Navigating the window to file:///etc/hosts is blocked; a notification permission request is denied.
  • Quitting sends SIGTERM and the server logs a clean shutdown.
