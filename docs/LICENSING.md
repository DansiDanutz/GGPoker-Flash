## Commercial hosting, forks and source

AGPL permits commercial use, paid hosting and competing forks that comply with it.
It does not require pull requests to DanGG. When conveying covered software, comply
with the applicable notice, license and source requirements, especially sections 4–6.
Under section 13, a modified version must prominently offer all users interacting
with it remotely over a computer network an opportunity to receive its Corresponding
Source without charge through a standard or customary means of copying software.
The license controls; an unrelated or older upstream source link is insufficient.

The login footer links source and software license without an account or subscription.
`dist/version.json` records the full commit and source URL compiled into the client;
`/healthz` reports that commit. The official deployment ships a committed, CI-green
main tree and passes its full `GIT_SHA`. Source links identify that immutable commit.

Build from Git with `cd app`, `pnpm install --frozen-lockfile`, then `pnpm build`.
Git supplies the commit by default. Archive/container builds must supply the full
40-character `GIT_SHA`. Independent operators must publish their actual modified
source and set `SOURCE_REPOSITORY` to their public repository with `/tree/<commit>`
URLs, including for Docker Compose builds. Commit changes before building; do not
label a dirty tree with an upstream commit. Keep source accessible for the periods
required by the license.

Download the complete repository tree/archive at the displayed commit. It includes
application/server source, Electron code, lockfile, build and installation scripts,
deployment templates, asset generators and committed inputs. Dependencies retain
their licenses. Supply any additional Corresponding Source your distribution requires.
Never publish production `.env` files, signing keys, credentials, databases or user
data. Building the committed app does not require proprietary GGPoker asset extraction.
